# Secure channel abort capability

`SecureChannel::abort_handle()` returns a cloneable `SecureAbort`. Obtain it before splitting or mutably borrowing `channel.tx` and `channel.rx`. `SecureAbort::abort()` synchronously marks the stream terminal, closes send credit, signals both receive APIs and link-budget waiters, and sends the existing reset frame once. It takes neither direction's borrow/lock and never clones encryption state. The capability has no routing, raw send, stream creation, or key access methods. Core remains safe Rust; the wire protocol is unchanged.

The handle holds only a weak reference to the existing mux ownership guard. Keeping or cloning it does not extend the stream, host/link or Noise key lifetime. Dropping the handle does nothing. Once both stream halves and any in-flight owners are dropped, abort is a harmless no-op. An abort racing the final drop may briefly upgrade that guard for the synchronous reset; normal last-owner cleanup still runs. Repeated aborts do not send extra resets. A separate channel's capability cannot affect this channel, even when numeric stream IDs are reused, because it identifies the original allocation.

Abort wakes writes blocked on either per-stream credit or the link DATA budget, and readers blocked on mux receive or AsyncRead. Subsequent encrypted send, receive and finish operations fail, including a receive that previously reached EOF. Local reset discards queued receive data logically instead of exposing it as successful post-abort input. Existing remote reset event ordering and error codes remain unchanged. Normal authenticated EOF and graceful half-close continue to permit traffic in the opposite direction.

A polled `SecureSender::send` arms an internal reset guard before encrypting. If it errors or its future is dropped while waiting after nonce advancement, the guard aborts the stream. Only a successful send disarms it. This prevents reuse of an encryption sender whose nonce has advanced without a confirmed local enqueue. Dropping an entirely unpolled send future has no effect. Oversized plaintext is rejected before encryption. This policy also covers an interrupted authenticated finish marker through its nested send.

Abort is cancellation, not a flush or remote acknowledgement. Already queued bytes remain potentially observable, and an operation already running concurrently with abort may have enqueued bytes before it observes cancellation. It cannot retract application mutations. A native adapter must gate new submissions, cancel via this handle, await its own reader/writer tasks, then release channel ownership. The abort call alone is not a join/drain receipt or permission to free memory borrowed by an outstanding C call. This seam does not cancel arbitrary local readers/writers supplied to `copy_from`, `copy_to` or `pipe`; their surrounding tasks still require adapter-owned cancellation. No native ABI, Swift integration, protected storage, comprehensive memory zeroization, or phone-runtime behavior is implemented here.

Tests use the existing local mux and actual Noise handshake harness. They prove a full-window write and simultaneous receive are pending before abort from outside both mutable borrows, a DATA-budget-blocked writer and AsyncRead unblock, repeated abort sends one reset, post-abort I/O fails, dropping a suspended encrypted send fails closed, weak handles do not retain stream/host/keys, and half-close remains bidirectional. Existing library, pinned-client and named-gateway tests cover adjacent behavior. Independent review is required before integration.

## Allocation retirement and numeric ID reuse

ABORT-01 showed that weak memory identity alone did not bind table cleanup: an old completed channel could reset/remove a new stream reusing its numeric ID. Each allocation now has a short retirement gate. Terminal Slot delivery, local finish/reject/reset, and final Guard drop elect exactly one cleanup owner; after retirement, old abort/drop can mark only the old local I/O terminal and cannot emit a reset or remove a route. Slot drop also retires detached allocations. A competing terminal delivery returns false while another path owns cleanup, so it cannot free the numeric ID during the owner's claim-to-remove interval. The gate is released before acquiring the host table for removal, avoiding the table/gate lock inversion. Stream hosts must insert a new slot only into a vacant entry, honor deliver's removal result, and stop admission before draining a dead link, and must not externally replace an occupied slot. Whole-link shutdown remains responsible for stopping admission.

Final DATA enqueue uses this same gate after waiting for link budget, so retirement cannot be followed by a stale sender's queued frame on a reused ID. FIN/reset, OPEN_OK and WINDOW enqueue are synchronous under the gate; no gate spans an await or direction lock. The unchanged independent Noise probe is run against the rejected parent and correction. Additional controls preserve a replacement across stale abort and final old-half drop, and pause a cleanup owner immediately before numeric removal while forcing competing FIN/reset delivery. Independent review of the correction remains required.
